InnoVision · My Quizzes (mobile)

The + button opens a drawer,
not a page

Right now the floating + leaves the list for a full page that collects two fields. These three options open a create drawer in place — name the quiz where you are, and the builder takes over from there. All three ride the existing vaul ResponsiveModal seam (drawer on mobile, dialog on desktop), reuse the clay drawer skin already shipped for Classes, and keep the "Create quiz" accessible name the e2e suite relies on. Every demo is live: tap the +, type, submit, use the grip.

Why it works

  • Fastest possible path: open → name → create → land in the builder. Three actions, zero decisions.
  • Every state already has a home pattern: inline role="alert" error, spinner-on-submit, success toast.
  • The dock stays visible behind the scrim — you never lose your place in the list.

Watch out

  • AI generation stays invisible — students who would benefit from it never discover it exists.
  • It does exactly what the page does today. If the drawer is the only surface, that's a ceiling.

Build notes

  • ResponsiveModal + DrawerContent — same seam as the Classes join drawer.
  • Focus moves to Title on open, returns to the FAB on close; Esc / scrim / grip all dismiss.
  • Create → close → router.push(/student/my-quizzes/{id}/edit) — unchanged POST payload.

Recommendation — Option 2, phased

Option 2 is the only one that gives AI generation a front door without taxing the common blank path — and its blank step is Option 1, so you can phase the work: land the drawer with the blank card first, then switch on the AI card when the builder accepts prefill params. If you want the absolute smallest diff today, ship Option 1 — nothing is lost, because Option 2 is a strict superset. Pick Option 3 only if the team is comfortable owning a hand-rolled segmented control.
