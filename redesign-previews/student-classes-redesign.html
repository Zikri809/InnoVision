Student classes — join drawer + card options

The join card is a form squatting on a dashboard: it eats ~40% of the mobile viewport on every visit, for an action you do maybe twice a semester. This preview moves it into a bottom drawer (the app already ships ResponsiveModal — vaul on mobile, dialog on desktop, keyboard-aware) and trims the class card. Every phone below is live — click, type, drag the handle.

✔ Drawer: agreed — one trigger, zero redundancy. Kills the sticky card, the dashed tile, and the empty-state form duplication in one move.
✎ Card: needs a trim, not a redesign — it's a navigation tile, and nav tiles want one row. Two directions below (A2 / A3) depending on how much personality you want.

The join drawer — native sheet with a clay twist

Opens from a floating action button pinned above the dock (the header key icon is the desktop counterpart). Inside: a 6-slot code scrubber built on shadcn's official input-otp (base-lyra ships it; clay re-skin per AGENTS.md) — each character lands in its own clay cell, caret auto-advances, the CTA arms itself at 6. Paste, keyboard, everything works. The success state replaces the sheet content for one beat, then dismisses itself — no "you joined" page, no toast hunt. Note the dock is now fully attached — flat, straight, full-width with just a top border — and the active tab keeps its original state (tinted pill), untouched.

Implementation notes (if you green-light this)

  • Attached dock is a shared one-liner: mobile-bottom-nav.tsx serves both roles, so changing the floating island (inset-x-3 rounded-[24px]) to a flat full-width bar (straight edges, top border only, no radius) lands for lecturer and student in one edit. The DockTab active state stays exactly as shipped; keep useKeyboardOcclusion translate-y wired to the new bar.
  • Code input = official shadcn input-otp (base-lyra ships it, deps: the input-otp package). Install via npx shadcn add input-otp, then clay re-skin per AGENTS.md — keep its hidden-input + aria-label wiring intact and put the stable aria-label="Join code" on it for the e2e helper.
  • Zero new dependencies beyond that. ResponsiveModal already does drawer⇄dialog, and its handleOnly repositionInputs config is exactly the keyboard-safe behavior this form needs.
  • Join logic is untouched — same /api/classes/join POST, 409 → "already enrolled" info toast, success → router.refresh(). Only the container moves.
  • E2E contract survives: keep aria-label="Join code" on the input and a /join/i-named button — helpers.joinClass keeps passing. The strict-mode single-instance rule becomes trivial: the form now exists in exactly one place (the drawer).
  • Card: keep A1 on desktop ≥lg (grid of chunky tiles suits the wide canvas), ship A2 below lg. A3 additionally needs the class code exposed to the student query (small API addition) — flag if you want it.
  • Success beat: swap sheet content to the check state for ~1.2s then auto-close; keep the existing success toast for screen-reader announcement (aria-live already handled by sonner).
  • i18n: new strings slot into student.classes in en.json/ms.json; old join-card keys retire once the sticky card dies.
