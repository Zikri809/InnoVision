## 0. Summary & interpretation (needs stakeholder sign-off)

**Interpretation of request #3 ("student authored quiz generate by AI"):** a
student creates their own private PRACTICE quiz by pasting text or uploading
material and having AI generate the questions into it. This matches the literal
phrase ("student authored") and the existing student-practice surface.
Rejected readings: (a) students *answer* AI-generated quizzes — that already
exists on the lecturer side and contradicts "authored"; (b) lecturers generate
from student submissions — no such workflow exists and nothing in the request
implies it. Deliberate scope choice: output lands in **private, ungraded**
practice quizzes (same as hand-authored ones today) — NOT graded classroom
assessments. Confirm on sign-off.

Sign-off checklist (answer before implementation starts):
1. F1 interpretation above correct? Practice-only output confirmed?
2. Roster photos (lecturers seeing student avatars) stay OUT of scope this
   round? (Moved here from open questions per review — deferring ≡ cutting,
   since nothing depends on it. Requires moderation stance + privacy review.)
3. Question images visible to students only after results are REVEALED on
   closed quizzes (D12 default)? Or immediately on close?

## 1. Goals

- G1: A student can create a practice quiz by pasting text or uploading a file
  (≤25 MB PDF/DOCX/PPTX/TXT/MD) and have AI generate ≤50 MCQ/TF questions into
  it, subject to existing DB caps (25 quizzes/student, 50 questions/quiz).
- G2: A lecturer can attach exactly one image (PNG/JPEG/WebP, ≤5 MB) to any
  question of their **draft** quiz; enrolled students see it during play and
  revealed-results review.
- G3: A student can attach one image to a practice question they authored;
  players holding a valid share code see it too.
- G4: Any user can set one profile photo (PNG/JPEG/WebP, ≤2 MB); it renders in
  their own app menu; removal restores initials. No other surface renders it.

## 2. Key design decisions

| Decision | Choice | Why / alternatives rejected |
|---|---|---|
| D1 Image column shape | `image_path text null` on BOTH `questions` and `student_quiz_questions`; path format `^<owner_uid>/<uuid>\.(png\|jpe?g\|webp)$` inside one private bucket `question-images` | Path-not-URL keeps signing server-side; owner-prefix enables orphan sweeps. URL column rejected (leaks signed URLs into rows). |
| D2 Read path | SECURITY DEFINER RPC `resolve_question_image(p_question_id uuid)` returns row `{image_path}` ONLY when caller may see that question's image (matrix in §3); app GET route exchanges id → short-TTL signed URL. Client never sees storage paths. | All authz lives next to existing views/RPCs; uniform empty-result → 404 (no oracle). Storage-policy EXISTS-subqueries rejected (can't express "knows share code"; also students have ZERO select on `questions`). Enumeration resistance: UUIDv4 ids + 60/min cap + uniform 404 = no practical oracle; returned path exposes only owner-uid+uuid (cosmetic). No pivot to `correct_index` possible — RPC returns only `image_path`. |
| D3 Upload path | `POST …/questions/[qid]/image` routes (lecturer + student variants): guard → CSRF → rate-limit → **declared content-length present AND ≤ cap pre-parse** (reject chunked/no-header requests — `request.formData()` buffers fully; header-trust alone insufficient) → sniff magic bytes server-side → fixed content-type/ext from SNIFF result (never client MIME) → admin-client upload → guarded column UPDATE → best-effort old-object removal ONLY after new upload succeeds | Mirrors proven `incident/route.ts` pattern; direct browser→storage skips sniffing (rejected). Replace race semantics: last-writer-wins on column; loser object becomes orphan until cleanup sweep (pinned by MEDIA-D5, §6). |
| D4 Avatar read/write | `POST/DELETE/GET /api/profile/avatar`; bucket `avatars`, path `<uid>/avatar.<ext>`; re-upload with different ext = delete old + write new (path not stable across ext); failed re-upload leaves previous avatar intact; overwrite always removes prior object after success | Single current avatar per user; no accumulation. |
| D5 Student AI input | Both text paste AND file upload. **Migration 0029 DROPS the `is_lecturer()` clause from the `"quiz-sources owner upload"` INSERT policy** (added by 0007_ai_generation.sql:250–257 — students cannot upload today; the draft-v1 claim that they can was wrong). Widening restores 0003 owner-folder semantics for all authenticated users; bounded by the bucket's 25 MB/file limit + owner-folder isolation. Student uploads use folder contract `${uid}/${studentQuizId}/…` so `sourcePath` validation composes. Harness probes: student-upload-allowed ✓ / cross-uid-denied ✓ (MEDIA-D9). Alternative rejected: a second mediated upload route for sources (more surface, no added safety over owner-scoped RLS for non-biometric material). | Zero NEW storage surface; identical extraction UX. The widening is EXPLICIT and probed. |
| D6 Student AI save | Definer RPC `save_student_quiz_questions(p_quiz_id uuid, p_questions jsonb, p_mode text)` mirroring EVERY 0025 protection (full list §3): takes NO title/source params and performs NO quiz-metadata mutation (intentional divergence from lecturer RPC); `updated_at` bumping inherited via existing `student_questions_touch_parent` trigger — not reimplemented | Per-question append loop = N round trips + partial failure; 0025 is the precedent. Advisory-lock namespace pinned VERBATIM to the 0023 append key (see §3) so bulk saves serialize against single appends — different namespace would defeat the 50-cap under concurrency. |
| D7 Student AI guard | `/api/student-quizzes/[id]/generate`: requireStudent + requireStudentQuizOwner + CSRF + rate **5/h/user in-memory** PLUS a **DB-side daily counter** (`ai_generation_usage(user_id uuid, day date, count int)` upsert-checked in-route, service-role) because signup is uninvited and in-memory limits reset on restart/don't aggregate across instances — this is a money endpoint. Body cap 512 KB; `extractedText` ≤400k chars (Zod); auth-before-parse. Note: generation inherits the lecturer route's long-budget/local-deployment posture (route.ts:30–33 comment) | Students are the abuse population; DB caps backstop. |
| D8 Shared validation lib | `src/lib/media/validation.ts`: `sniffImageType(buf)` (PNG/JPEG/WebP magic bytes incl. truncated-header rejection), size caps, declared-length gate, ext/content-type mapping, **path-format validators** (`isValidAvatarPath`, `isValidQuestionImagePath`) asserted immediately before every `createSignedUrl` — never trust stored columns blindly (kills traversal/`../` regardless of how a bad value got there; mirrors generate-quiz route's `..`//normalize checks) | One implementation for both upload routes; pure + unit-tested. Incident video logic untouched. |
| D9 Rendering | Players/builders/results render `<img>` from signed URL fetched via `GET /api/question-images/[qid]` (wraps D2 RPC + signing; returns `{url, expiresAt}`; 60/min). **Expiry-aware cache** in `use-question-image.ts`: store `expiresAt`, refetch when stale, retry-with-backoff once on `<img>` error — survives multi-hour sessions/reconnects. Layout: fixed max-height container + `object-contain`, image sits ABOVE options so options/CTA never shift off-screen mid-assessment (incl. under gesture overlay). Broken/expired image: reserved minimal space + `aria-hidden`, NEVER blocks answering. Alt text = auto-derived truncated prompt excerpt (decorative-fallback semantics) | Proxying bytes through Next rejected (bandwidth, no safety gain). CSP: when enforcement happens later, `img-src` must add the storage origin in the same PR — named rollout item R-CSP (§7). Current CSP stays Report-Only. |
| D10 Cleanup | Deleting a question: clear column FIRST, then remove object best-effort (failure mode = orphan, not broken render). Whole-quiz delete cascades rows with no per-object hook → **`scripts/media-cleanup.mjs` is a committed M0 deliverable** (not someday-cron): sweeps objects unreferenced by both question tables + avatars unreferenced by profiles; `--dry-run` mode; cron expectation documented like migration 0020 did | Free tier is 1 GB (COSTS.md §2.2); student-owned quizzes make unbounded orphans likelier. Supabase storage has no transactional coupling with Postgres. |
| D11 Generate-route reuse | **Option A (preferred):** student generate route COMPOSES existing lib functions (`lib/ai/quiz-prompt`, `lib/ai/quiz-schema.aiQuizToRows`, `lib/ai/client.chatCompletions`) with ~50 lines of glue duplicated from the lecturer route. Option B: extract `generate-core.ts` only IF measured duplication exceeds ~100 lines. Lecturer route behavior must stay byte-identical either way (pins exist; see §6 blind-spot fixes) | Refactoring a battle-tested route pinned only through-the-route buys little for a 3-line request. |
| D12 Closed-quiz visibility | `resolve_question_image`'s assessment branch gates CLOSED quizzes on the SAME `is_student_reveal_allowed(quiz_id)` predicate used by results views — an image can itself encode the answer, so image access follows score-reveal, not merely quiz-close. Live quizzes: enrolled ⇒ visible (they're answering now). | Consistency with §7.9 secrecy doctrine; closes a leak the v1 matrix covered "by accident". Sign-off item #3. |
| D13 Share-code images | Shared-practice images sign with a SHORT TTL (**300 s**) vs 60 min elsewhere; unshare nulls `share_code` → new mints die instantly; previously-minted URLs decay within TTL | Capability = code, codes are revocable; bounds the post-unshare residue honestly (v1 overstated immediacy). |

```

-- incident-footage in 0020_integrity_suite.sql:471–476; uploads/signing ride

       ('avatars','avatars',false,2MB,'["image/png","image/jpeg","image/webp"]')

-- protect_profile_restricted_columns guards only role/consent_given_at (0019:360–387).

create function public.resolve_question_image(p_question_id uuid)
returns table (image_path text) security definer set search_path = public ...
-- Visibility matrix (each row = independent branch, else NO rows → upstream 404):
--   A. assessment question q → quiz k:
--      caller is class owner (any status incl. draft/closed)            → row
--      caller enrolled AND k.status='live'                              → row
--      caller enrolled AND k.status='closed'
--        AND is_student_reveal_allowed(k.id)                            → row   (D12)
```

## 4. API surface

Standard preamble everywhere (guard → checkSameOrigin → rate-limit → body-cap
→ parse → Zod → business → typed errors; no-oracle 404s). Multipart routes
additionally enforce: **declared Content-Length present, parseable, AND ≤ cap
before any formData() buffering** (chunked/absent header → 413).

| Route | Method | Guard | Rate | Notes |
|---|---|---|---|---|
| `/api/quizzes/[id]/questions/[qid]/image` | POST/DELETE | requireLecturer + requireQuizOwner-of-qid; **draft-only** (live→409) | 20/h | ≤5 MB; sniff-driven type/ext; replace = upload-then-delete-old |
| `/api/student-quizzes/[id]/questions/[qid]/image` | POST/DELETE | requireStudent + requireStudentQuizOwner | 20/h | same validator |
| `/api/question-images/[qid]` | GET | authenticated; visibility via `resolve_question_image`; path-format validation before signing | 60/min | `{url, expiresAt}`; TTL 3600 s (300 s when resolved quiz is shared-practice, D13) |
| `/api/profile/avatar` | POST/DELETE/GET | requireUser (self only) | POST/DELETE 10/h; GET 120/min | ≤2 MB; GET → signed URL or 404; path regex `^<uid>/avatar\.(png\|jpe?g\|webp)$` before signing |
| `/api/student-quizzes/[id]/generate` | POST | requireStudent + requireStudentQuizOwner | 5/h in-memory + daily DB counter (D7) | body `{extractedText? \| sourcePath?, questionCount ≤50, difficulty, language}`; sourcePath prefix-checked `${uid}/${quizId}/…`; atomicity: invalid AI output after 1 retry ⇒ 422, ZERO rows |

Lecturer `/api/ai/generate-quiz`: UNCHANGED behavior; students calling it get
403 (requireLecturer already pins this — keep).

## 5. Frontend

### F1 — dialog reuse is REAL work (per review finding)

`GenerateFromFileDialog` today hardcodes `fetch("/api/ai/generate-quiz")`
(line ~246), posts a lecturer-shaped body (`sourcePaths[]`,
formatDistribution, steeringPrompt), and expects `{quiz, questions}` where
`quiz` is a lecturer row. Required changes:

- New props: `endpoint: string`, `mode: 'lecturer' | 'student'`, and an
  `onGenerated(questions)` callback (or student-shaped success contract
  `{questions}`); lecturer call sites pass current values unchanged.
- Student mode hides: steering prompt, format distribution. Keeps: count,
  difficulty, language (defaults from student locale — resolves sign-off Q1).
- OCR config: `OcrConfig` continues to be injected server-side into the page
  (student edit page gains the same injection the lecturer builder has);
  engine picker + localStorage persistence work unchanged.
- Success path: student editor reconciles via its own
  `setQuestions`/refresh strategy (NOT the lecturer router-refresh shape).

Student editor (`my-quizzes/[id]/edit/editor-client.tsx`) additionally gets
the F2 attach/remove UI on its question cards (its `EditorQuestion` type has
no `image_path` today — extend type + card + dialogs). "Generate with AI"
button opens the dialog in student mode.

### F2

Lecturer builder question cards + edit-question-dialog: Attach/Replace/Remove
image (upload → preview → save). Render surfaces: assessment play-client,
practice player-client, results breakdown — all via `use-question-image.ts`
(D9 cache/layout/fallback rules).

### F3

`Avatar` component (initials fallback) in `app-user-menu` + settings entry;
upload/preview/remove via `/api/profile/avatar`; removal → initials
immediately (explicit acceptance criterion).

i18n: budget ~25–40 new keys × en+ms across builder cards, edit dialog, two
players, results breakdown, avatar menu/settings. `check:i18n` gates CI.

## 6. Testing plan

  convention for node-leg binaries — no fixtures): PNG `\x89PNG\r\n\x1a\n`,
