### Step 2 — `lib/gestures` (pure logic, Node-unit-tested)

## 4. Robustness / edge-case matrix

| Area | Guard |
|---|---|
| Webcam/MediaPipe unavailable (headless CI, no camera, insecure context, venue Wi-Fi, slow boot) | Whole-boot `Promise.race` (`BOOT_TIMEOUT_MS = 10s`), `getUserMedia` guarded + `max`-bounded, GPU→CPU fallback, model 404 → `status: "off"` → passthrough. `booting` renders children as-is (clickable). Losing `getUserMedia` tracks stopped. Existing E2E is the regression proof. |
| Stale frame-handler closure (wrong question / stale optionCount) | Latest-ref dispatch: `frameHandlerRef` + `stateRef` reassigned every render; frame handler reads only refs; callbacks via `onSelectRef`/`onNextRef`/`onHoldRef`. Finger input gated on `status === "active"`. |
| Calibration→PIP element remount | **One persistent** `<video>`/`<canvas>` pair, re-positioned via CSS; never conditionally mounted. Tracker holds the same nodes for both states. |
| Palm-next sharing the answer accumulator | Two `HoldConfirm` refs (`answerHoldRef`, `nextHoldRef`); palm-next never routed through `onHoldProgress`. |
| Stale palm-next racing `timeUp`/submit | `goNext` gains `if (phase !== "feedback") return;`; palm-next gated on `nextArmed` (feedback only). |
| Same-length consecutive questions | Scan countdown + hold reset keyed on `questionId` (not `optionCount`). |
| Accidental lock (finger flicker / change mid-hold) | `HoldConfirm` resets on any finger change (U-G4); scan countdown disarms between questions; E9 proves no premature answer. |

## 5. Risks / open items

- **Hand-loss pause is client-side only (deliberate deviation, documented).** TESTING E9b says the quiz goes `paused` and answers are blocked; P6 satisfies this with a client-side overlay and does **not** flip `quiz_sessions.status` — because P7's server `paused` state has no recovery route yet (no self-recover/unlock until P7), a server-side pause would strand the student. P7 should adopt hand-loss into the server state machine (it can reuse `HandLossMonitor`). E9b pins the "no DB status change" via the recovery answer returning 200 (not 409 `session_not_active`), since no `GET /api/sessions/[id]` exists. The quiz timer keeps running during the client pause (matches PLAN §1 `paused` semantics). The pause clears only after a continuous-present stabilization window (`PAUSE_CLEAR_MS`) so a brief hand flicker cannot unlock mid-hold. This is the biggest scope decision; flagged for review.
- **Real hand tracking is manual-only in P6** (TESTING §7.1). The fake tracker proves the state machine and wiring; real-lighting reliability is a manual pre-demo checklist item. Accepted per TESTING §1/§7.
- **Vendored MediaPipe assets in git** (~10–11 MB). Docs say "committed or fetched via postinstall"; committing keeps CI deterministic (no Google CDN in CI). Integrity: SHA-256 pin + `MANIFEST.json` + `verify-mediapipe.mjs` **enforced in `ci.yml`** (a step after `npm run build`). If repo policy prefers not to commit binaries, the fallback is a `postinstall` fetch — but that makes CI network-dependent; committing is the locked choice.
- **Fake-tracker global is a test seam in production code, gated to non-prod.** Read-only, client-side, and a student could already click; gating to `NODE_ENV !== "production"` + shape validation removes the extension/3P-script concern. Documented in code + §2. Long-term: `trackerFactory` prop.
- **Turbopack + `webpackIgnore` dynamic import.** Next 16 defaults to Turbopack; the pragma is webpack-specific. Step 7 includes a verify-once smoke with a documented fallback (`<script type="module">` + `globalThis`).
- **`@mediapipe/tasks-vision` exact pin vs vendored bundle.** Types from the package, runtime from the URL; the exact pin + vendor-script version check keeps them in sync.
- **Scan countdown constant is UX timing, not a gate test.** Exported from `lib/gestures/constants.ts`; `waitForScanClear` uses the overlay, not the constant, so timing changes don't break E2E.
- **No unit coverage for `hand-tracker.ts`** — browser-only (MediaPipe + DOM). Manual checklist + E2E (fake) cover it. Matches the tesseract/glm-ocr/vision precedent.
- **Palm-next is now gate-tested** (E8 holds 5 → auto-advance), so it is no longer untested scope. If review still considers it creep, it can be dropped (click Next remains primary) without affecting U-G1–U-G7/E8/E9/E9b.
- **Hand-loss detection pauses when the tab is hidden** (rAF stops). Harmless in P6 (no server advantage), but P7's server-side `paused` must add a `visibilitychange`/`blur` fallback or a student could tab-away to avoid re-verification. Documented in the hand-tracker header for P7.
- **CSP / Permissions-Policy is out of P6 scope but recommended (P9 hardening).** P6 is the first phase to ship WASM + camera; the plan notes a CSP (`script-src 'self' 'wasm-unsafe-eval'`, `media-src 'self' blob:`, `Permissions-Policy: camera=(self)`, `frame-ancestors 'self'`) as a P9 item — adding it now is risky (could break the vendored bundle); validate in P9.
- **Plan drift:** none — stack/env align with PLAN.md (Next 16.3.0, no new env, no DB changes; the only new dependency is `@mediapipe/tasks-vision`, which PLAN.md §5/§7 already assumes).
