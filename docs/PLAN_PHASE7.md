## 4. Robustness / edge-case matrix

| Area | Guard |
|---|---|
| Student forges `matched=true` | RPC computes from stored vs submitted raw embedding; no verdict param; `face_checks` RPC-write + select-only + RLS owner/lecturer. |
| Direct embedding UPDATE | Actor-bound guard trigger (own/other/borrowed-GUC/service-role blocked — D-probes). |
| Replayed verify | Nonce checked+rotated in the locked RPC (D14/I5c); stale nonce → refetch + **one** retry; `suspected_replay`/`too_frequent` advisory flags. |
| Window laundering (V/−V alternation) | **FLAT last-5:** continuous alternation → hard-flagged at the 6th check (`F,P,F,P,F`; test pinned). **Bounded** alternation (≤2 fails per 5-window) is never hard-flagged but leaves a visible ≤2-fail record + advisories + a paused→blink-recovery churn per fail — **an occasionally-failing integrity signal, never a silent clean history** (iteration-3 security 1). |
| Concurrent verifies / verify-vs-answer | `for update` serializes; `verifyLock` + `pendingVerifyRef` (deferred, never dropped; terminal-cancelled). |
| Threshold / grace forgery | SQL constants only. |
| Wrong dims / NaN / empty | `z.array(z.number().finite()).length(192)` → 400; `::vector` cast → typed error. |
| Verify on completed/non-assessment/closed/non-enrolled/revoked | Typed `session_not_active`/`not_assessment`/`quiz_not_live`/`not_enrolled`/`consent_required`. |
| Gate bypass by reload | `hasFaceChecks` seeding + pinned precedence; `'ready'` requires ≥1 check. |
| Answer-409 stale mirror | On 409 the client GETs the real status and branches (paused→question; flagged→question unless alreadyTimeUp; completed→dead). |
| Single fail after unlock | FLAT window: pass returns `active` for that check but does not clear standing fails; a later fail re-flags (integrity-conservative). E7 (unlock→pass) is deterministic. |
| Submit while paused/flagged | Paused → allowed (timeUp auto-submit works); flagged → rejected (lecturer decision; flag never erased). |
| `submitNow` failure branches (hot-loop) | Every non-terminal branch uses `phaseRef.current === 'timeUp' ? 'timeUp' : 'question'` — the `remainingMs`-effect guard terminates; Retry-submit stays reachable (iteration-3 robustness 1). |
| Timer through gate/recovery/paused | Runs from `started_at`; `timeUp` auto-submits score-0; flagged-timeUp 409 → `timeUp`; gate shows the countdown (presentational prop); E2E pin. |

| Verify response lost after rotation | `nonce_mismatch` → refetch + retry **once**; then surface state — no loop. |
| 5-frame capture | Exactly 5 VALID; nulls don't count; 15-attempt/10s cap → `capture_failed`. |
| Blink timeout | `LIVENESS_TIMEOUT_MS` → `failed` → gate re-offers liveness. |

## 5. Risks / open items

- **⚠️ POST-APPROVAL DEVIATION — face embedding model.** The plan pinned a `FaceEmbedder` task + `face_embedder.task` (192-dim) from `@mediapipe/tasks-vision`. **THAT TASK DOES NOT EXIST** — verified against `1.0.1` and the latest RC (no `FaceEmbedder`/`FaceRecognizer` class; the model URL `storage.googleapis.com/mediapipe-models/face_embedder/...` 404s). Implemented instead: a **swappable `FaceEmbeddingProvider` interface** (`src/lib/face/types.ts`) with a default `ImageEmbedderFaceEmbeddingProvider` (`face-tracker.ts`) consuming a self-hosted 192-dim TFLite model at `public/models/face_embedding.tflite`. **That file is a MANUAL DROP-IN** (the legacy `face_recognition.tflite` is no longer vendorable). Until present: the manifest records it `missing` (verify-mediapipe passes with a warning) and the pipeline reports face `'unavailable'` (click-first passthrough). To enable: drop a 192-dim face-embedding TFLite at `public/models/face_embedding.tflite`, re-run `vendor:mediapipe`, commit the manifest. The 192-dim `vector(192)` schema + cosine + ALL server logic are unchanged; swap the provider to use any future model. All E2E uses the fake seam, so the pipeline is fully tested regardless.
- **Anti-replay is honest, not magic.** The nonce stops *naive captured-request* replay; it cannot stop a student looping their own uploaded embedding. **The FLAT window hard-flags continuous V/−V alternation at the 3rd fail in any sliding 5-window; bounded ≤5-check framing leaves a visible ≤2-fail record + advisory flags — an occasionally-failing integrity signal, not a clean history** (iteration-3 security 1). True identity needs post-MVP challenge-response / device attestation (PLAN risk 8).
- **Deviations from PLAN §2 API table:** (a) `GET /api/sessions/[id]`; (b) `POST /api/sessions/[id]/pause`; (c) `POST /api/face/consent`; (d) `POST /api/sessions/[id]/face-unavailable`. All authZ'd, rate-limited, RPC-backed.
- **`submit_session` semantics change (deviation from §1 prose):** `paused` submits; **`flagged` submits rejected** until a lecturer decision. No existing test pins the old behavior.
- **Consent revocation has an integrity consequence:** revoking mid-assessment flags in-progress sessions; re-consent does not un-flag (lecturer decision). Deliberate; documented on the revoke UI.
- **Timer counts gate time:** a timed assessment can auto-submit score-0 if it expires during the gate/blink (pinned by the timer-gate E2E). Demo-killers are UNTIMED.
- **Post-unlock single-fail re-flags** (integrity-conservative); only a pass clears the current check. E7 (unlock→pass) is deterministic.
- **Camera-off / persistent-camera-death students** complete assessments click-first (PLAN risk 7 accepted) and are **recorded** (`face_unavailable_at` boot / FLAT-window flags for mid-quiz nulls); the click fallback + lecturer exempt are the safety net; the gate is skipped only when tracking is truly unavailable.
- **Client-computed liveness (blink) is spoofable** — accepted MVP limitation; server enforcement is nonce + cadence + lecturer decision.
- **The flagged/unlock poll** is per-session (60/min cap), survives `timeUp` while flagged, stops on terminal phases.
- **~13 MB face models committed** — SHA-256 + manifest + CI `verify:mediapipe`.
- **P7 exposes only routes + minimal status reads for lecturer actions** — the results dashboard (unlock/exempt buttons, face-check timeline incl. `suspected_replay`, `unavailable`, revocation markers) is P8.
- **CSP/Permissions-Policy (P9):** still deferred (`media-src 'self' blob:`, `Permissions-Policy: camera=(self)`).
- **E2E availability assumption:** unseamed face boot must fail fast (headless camera denial) for the mouse-based assessment E2E to stay green; E5/E11 get timeout belt-and-braces; the seam is never installed there.
